# Discovered flight routing: sources and limits

World-map markers show a padlock when `C_TaxiMap.GetTaxiNodesForMap` explicitly marks a stop undiscovered. Forever returned `isUndiscovered=false` for both learned Stormwind (2) and unlearned Light's Hope Chapel (67) on the same character. Only a current or reachable stop recorded in that character's flight window earns a green check. Other stops show a plain boot. Map status alone never adds an itinerary to the planner.

`Flights.lua` is generated by `tools/build_flights.py` from the pinned `tools/data/native-flights-70959.json`. Its SHA-256 is embedded in the runtime data. It supplies geometry and metadata, **never character flight discovery**. No other addon is required.

The native Forever build 70959 snapshot supplies TaxiNodes (FileDataID 1068100), TaxiPath (1067802) and TaxiPathNode (1000437). The pinned JSON preserves original DB2 hashes, source IDs, native XYZ, faction flags, class cross-checks, excluded records and approach evidence. Existing MIT OpenMap build 70245 data was used as an independent class/faction comparison, not as affirmative discovery. See the existing OpenMap attribution in `SOURCES.md` and `Libs/`.

There are 65 eligible normal flight masters and 286 unique directed segments: 138 Alliance, 146 Horde and two shared. Special/scripted and battleground paths, undiscoverable nodes and the special druid flights are excluded. Native low faction bits are checked against the live player faction; unknown faction/class/identity fails closed. Native node IDs differ from CharacterBitNumber and transient flight-window slot indices.

Availability is learned read-only from an open flight-master window, using [Forever's native taxi APIs](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/TaxiMapDocumentation.lua) and [flight-map provider](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_FlightMap/FM_FlightPathDataProvider.lua). Global `GetTaxiMapID()` and `C_TaxiMap.GetAllTaxiNodes()` identify stable node IDs. Current (0) and Reachable (1) positively record discovery; Unreachable (2), absent, unknown and map-transition records do not. Data is isolated by validated player GUID and native build; a faction/class change invalidates prior offers.

Only actually offered **directed whole itineraries** become graph edges. Visit each source master to record its offerings. `TaxiNodeCost(slot)` is the complete quoted fare; `GetNumRoutes()` / `TaxiGetNodeSlot()` resolve the offered hop slots to native IDs. An intermediate hop does not unlock that destination. Reverse offers are never inferred. Incomplete/cyclic/unmatched hop data omits flight geometry rather than drawing a guessed shortcut. No `TakeTaxiNode`, protected button automation or flight booking is performed.

Quoted prices are historical, labelled **last quote** and refreshed at the master. Native base fare sums are labelled estimates if a complete native itinerary matches but no quote is readable. Otherwise fare is unknown, never silently free. Known/estimated fares are checked against readable current money, including the sum across separate flight legs; actual price may change with reputation or server rules. Reopen the flight window to refresh prices. Timing uses native 3D polyline length / an assumed 32 yd/s plus 20 seconds of manual selection allowance. It is not measured server travel time. Mixed search retains its bounded, short-zone-itinerary-first policy and does not promise global time/cost optimality.

Fifty masters use permitted exact native ground handoffs. Fifteen need explicit manual platform/building access; 14 of those have permitted handoffs supported by native position/height and town or exit-component evidence. Hammerfall and Aerie Peak use separate nearby ground points within 100 yd; the connection to the actual master is manual and not drawn as a certified walking path. Stormwind uses exact native master XY/Z on component 52, shared with its verified Elwynn exit; the existing terrain path to that exit is 281.45 yd. Its previous component-36 handoff was disconnected and caused Southshore-to-Goldshire to select Sentinel Hill. The pinned correction and generator connectivity check prevent that regression; no walking permission was added. Stormwind, Ironforge, Undercity and other raised/indoor masters retain native TaxiNodes pad Z, never the overhead root terrain/roof height. Platform/interior access remains manual. **Freewind Post has no verified destination handoff** and is unavailable as an arrival; a positive live interaction can still authorize boarding outward.

A live source interaction can prove the player is already at a flight master on an otherwise blocked terrain cell. That short-lived private boarding snapshot survives cooperative planning and taxi-window closure without granting walking access. Flight departure requires positive `UnitOnTaxi("player")` evidence; UI closure alone is not takeoff. Airborne guidance hides the walking arrow. Arrival requires readable on-foot state, destination proximity and native-height checks. Protected height may require Continue on foot at the destination. Loading elapsed time is excluded from stable landing evidence. An early landing requests one transactional replacement after stable on-foot evidence; failure preserves the previous journey.

Research/replay artifacts are in `../output/flight-audit-70959`: `audit.py` and `refine-runtime-approaches.py` extract the initial candidates from the read-only snapshot. The pinned JSON also contains the subsequently verified Stormwind exit-component correction; retain that connection proof when refreshing candidates. Compile with `tools/build_flights.py`, which validates its exit connectivity. `tests/flight_destination_choice.py` compares real Southshore-to-Goldshire journeys via both landings. Live-client flight selection, city/platform access, landing detection, fares and third-party compatibility still require acceptance testing.
