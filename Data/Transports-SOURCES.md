# Scheduled transport sources and limits

A player screenshot places the dock end of the Booty Bay–Ratchet gangplank at approximately 26.0, 73.2 in Stranglethorn Vale. Outbound guidance uses this observation for the final approach. The vessel stop supplies the aim for boarding and the ship's travel geometry.

`Transports.lua` is generated by `tools/build_transports.py` from the pinned `tools/data/native-transports-70959.json`. The source hash is bundled in the Lua record. No runtime addon/database dependency is required.

The native Forever build 70959 snapshot supplies TaxiPath (FileDataID 1067802) and TaxiPathNode (1000437), converted with the matching installed WoWDBDefs layouts. Original DB2 hashes, path/node IDs, native positions, flags, delays, ownership evidence and ground-height proofs remain in the pinned JSON. Route identity uses stop positions and the existing MIT OpenMap route inventory, not legacy TaxiPath From/To node IDs. Existing OpenMap credit/license remains in `SOURCES.md` and `Libs/`.

The dataset contains 12 passenger services and **25 directed consecutive-stop links**: Ratchet/Booty Bay; the three Horde zeppelins; Menethil/Theramore; Rut'theran/Auberdine; Feathermoon/coast; Menethil/Southshore/Auberdine; Steamwheedle/Powderfuse; Alterac/Zephras; Mulgore/Zephras; and Auberdine/Stormwind. Stops use flag 2 and sort by native NodeIndex. The circular service is Menethil to Southshore to Auberdine to Menethil; no reverse trip is invented. Repeated Feathermoon stops and flag-1 teleports are preserved. Geometry is split even when a teleport stays on the same continent. Legacy path 295 and one-stop path 436 are excluded with reasons in the audit.

Faction fields are conservative routing recommendations based on port ownership, **not physical boarding restrictions**. Neutral ports remain available to either faction. Native Dalaran Area279/mask2 supports the Alterac airship's Alliance recommendation; Mulgore Area215/mask4 supports its Horde recommendation. Both Zephras endpoints occupy Valanaar Area16638/mask0, using UiMap2521 on native instance2991. Unknown player factions can use only verified neutral services.

Every walking handoff is an existing permitted dry ground point within 300 yards of the native vessel center. The final pier or tower access is **manual boarding**, not a certified walking connector. Exact MCVT triangle heights, base elevations, holes, liquid and slope checks are pinned for all 25 distinct approaches. The Mulgore vessel's Zephras handoff was refined after an aggregated dry pixel failed the exact native slope check. No terrain permission was added. Ground height also prevents resuming ground guidance while still on an elevated deck; protected height can require the explicit Continue on foot action at the destination approach.

Town-region checks corrected isolated nearest-pixel handoffs in Booty Bay and Dalaran. Booty Bay joins its actual flight/mail/inn region; its native flightpoint walking leg is 324.464 yards. Dalaran's mailbox-to-handoff path is 47.412 yards. Stormwind's earlier city-region fallback has been replaced by the certified static pier floor, 13.289 horizontal yards from vessel node 177218, with native city-to-harbour and pier walking corridors. See `HarbourAccess-SOURCES.md` for proof bounds and the remaining middle-harbour detour. Boarding the vessel remains manual. Nearby town anchors were unavailable for Steamwheedle/Powderfuse; their dry endpoint evidence still needs live acceptance.

Timing is an estimate, not a live schedule. Cached type-15 records exist only for Moonspray (176244/path293), Serenity's Shore (176310/path11167) and Mistbound (656308/path11616), with native movement speed30 and acceleration1. Field meanings were checked against [TrinityCore's native game-object schema](https://github.com/TrinityCore/TrinityCore/blob/master/src/server/game/Entities/GameObject/GameObjectData.h); no implementation code is copied. Those estimates use same-piece native polyline length/speed plus an acceleration allowance. Other services use a disclosed 180-second ride assumption for planning. A 120-second waiting assumption applies at initial boarding. A same-vessel continuation replaces another waiting assumption with the native intermediate dwell. These values do not measure server phase, spline curvature, loading time or actual queue time.

Mixed search retains the existing work bounds and first tries a feasible short zone itinerary, then the unrestricted graph. Time cost ranks available legs, with admissible distance/cost pruning. It does not promise a globally fastest route. Walking distance excludes sailing geometry. Route previews distinguish approximate total journey time from walking distance; native transport lines are blue and never join across manual boarding gaps or teleport splits.

Research/replay artifacts are in `../output/transport-audit-70959` (`audit.py`, `augment-ground-heights.py`, native CSV/DB2 and `runtime-inventory.json`). The original snapshot stays read-only. Live-client boarding, timing, tower access and disembarking acceptance remain required.
